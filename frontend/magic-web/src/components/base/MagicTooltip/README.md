# Tooltip 使用规范

本规范适用于 Magic Web 普通按钮说明和截断文本提示；复杂浮层继续由对应业务组件维护。

## 先判断用途，再选择组件

| 需求 | 使用入口 | 规则 |
| --- | --- | --- |
| 图标／图片按钮没有可见名称 | `MagicTooltip` | title 是简短动作名；触发元素就是按钮；按钮具有本地化 aria-label |
| 有文字的按钮需要额外解释、快捷键或禁用原因 | `MagicTooltip` | 只写新增信息；不机械复制已显示的按钮文字 |
| 文本被省略，需要完整内容 | `SmartTooltip` | 必须确认对应文字实际截断；触发范围局限于文字区域 |
| 维护旧 antd 样式区域的单行省略 | `MagicEllipseWithTooltip` | 保留该区域体系，遵守相同的显示资格；新现代组件优先 SmartTooltip |
| 维护既有 MagicButton | `MagicButton.tip` | 复用它内置的提示，外面不要再包一层 Tooltip |
| 复杂内容、链接、按钮或播放器 | 现有 Popover / HoverCard / MediaPreviewTrigger 等业务入口 | 必须保留内容交互、焦点、关闭与加载责任，不按普通文本禁用 pointer events |
| 底层组合或有明确状态约束的组件 | `shadcn-ui/tooltip` 原语 | 由组件维护者完成 Trigger、Content、生命周期及说明；普通业务不另写同类包装 |

两种普通用途可以共享渲染和等待机制，不需要两个计时系统或新的全局 manager。图片本身如果是内容预览，使用媒体预览；只有它充当无文字操作按钮时才使用按钮说明。

## 默认行为

- 基于 Radix 的普通提示在鼠标 hover 后等待 700 毫秒，提前离开取消；默认不跳过后续进入的等待。键盘聚焦立即显示。`MagicButton.tip` 和 `MagicEllipseWithTooltip` 只同步进入等待，其他焦点和退出行为仍沿用 antd。
- 触发元素与提示内容都可悬停；允许在空隙内移动到内容。离开两者及安全区后关闭，Esc 可关闭，不用固定短时自动消失打断阅读。
- 已执行点击、菜单打开、重命名或拖拽时，相关普通提示不应重新弹出；使用所在组件已有状态控制，不监听全站 DOM 猜测。
- 关闭提示不能吞掉原按钮事件、改变焦点目标、重挂原按钮或转发一次人工合成点击。
- 普通提示无业务点击动作；不能因为气泡无按钮就推导出全局 pointer-events none。
- 页面中的必需信息和唯一操作入口不能仅存在于 hover；触摸设备沿用已有可点击入口，不自动添加长按手势。

## 显示资格与触发区域

- 名称未截断就不弹完整名称。尺寸改变后应使用当前显示尺寸判断，不根据字符串长度猜测。
- 单行、多行、省略和嵌套富文本分别按真实裁切节点判断；支持嵌套不等于给包含名称和所有按钮的整行添加提示。
- 操作按钮位于名称提示触发区之外；不要把整张卡片、整行或多个不同动作统一包入一个名称 Tooltip。
- 同一目的只保留一个提示入口，避免同时使用原生 `title`、antd Tooltip 和 MagicTooltip 重复显示；确有独立语义时分别定位。
- 现有受控展示、额外元信息、媒体预览不是「溢出提示」，不能仅因文字显示完整就删除。

## 位置、尺寸与阅读

- 同排左右相邻的操作，名称提示优先上方或下方；文字起点对齐，避免向右覆盖更多／下载等操作。
- 垂直图标侧栏可向外侧显示，保持对应关系；不把所有位置写死为同一个方向。
- 普通包装默认间距 4 像素；依赖既有定位引擎翻转和可用宽度。普通短文本最长宽度受可用空间及 20rem 限制，自然换行，不再次省略正文。
- 不通过抬高所有按钮或压低所有提示处理局部遮挡。全屏容器和编辑器局部层级继续由原 owner 决定。
- 空间不足以同时阅读长内容和操作时，评审该场景的已有详情／展开入口。不要让气泡越长越大，也不要承诺定位库能猜出用户的下一步点击。

## 内容、状态与性能

- 操作说明使用已有 i18n；文件名、项目名展示原始业务文字，不新造持久化副本。
- 图标按钮必须有可访问名称；视觉提示出现与否不应决定屏幕阅读器能否知道按钮用途。
- 禁用原因说明与「禁止 Tooltip 展示」不同：前者描述按钮为什么不可用，后者控制当前是否显示。不能混用按钮 disabled 和提示 disabled。
- 控制器持有菜单／拖拽／预览状态，Tooltip 消费所需布尔条件；不再复制一套状态。
- 文字提示只使用已加载内容；不因 hover 请求完整文件树、不深拷贝附件、不扫描全页面、不每个文件额外安装持续监听器。
- 专用时序必须在调用点说明用途和退出条件，不用随意的 `0`、`200` 取代公共默认。已存在的专用时序需先理解，不因本规范发布自动删除。

## 维护边界

- 新增或修改普通 Tooltip 时遵循本规范；历史直接 antd、独立 Canvas 和媒体浮层不是自动迁移范围。
- 修改底层前分别检查普通说明、截断文本、富内容和企业消费者；不能只按名称包含 Tooltip 批量替换。
- 不因为统一规范顺便删除旧 props、重命名旧组件、修改文案、变更 hover 菜单或重构状态管理。
- 本 README 记录稳定契约和取舍；临时调查、责任提交、部署状态、方案批准记录不放入正式组件规范。

## 使用示例

图标按钮使用已有动作文案，同时提供可访问名称。菜单打开时只禁用说明，不移除按钮。

```tsx
<MagicTooltip title={t("common.more")} disabled={menuOpen}>
	<button type="button" aria-label={t("common.more")} onClick={openMenu}>
		<MoreHorizontal size={16} />
	</button>
</MagicTooltip>
```

完整名称只覆盖文字区域。`fileName` 未截断时不出现提示，右侧操作按钮独立于名称触发区。

```tsx
<div className="flex items-center gap-2">
	<SmartTooltip
		className="min-w-0 flex-1"
		placement="top"
		align="start"
		disabled={menuOpen || isDragging}
	>
		{fileName}
	</SmartTooltip>
	{moreButton}
</div>
```

已有可见「保存」文字的按钮无需再用相同 title 包装；若确需说明快捷键或禁用原因，title 只提供这部分额外信息。新图标说明不使用 `SmartTooltip forceShowTooltip`；这个参数继续保留给既有消费者。
