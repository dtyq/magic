# iBox 3.0

## Overview
iBox 3.0 是新一代数字藏品交易平台的移动端界面，专注于为用户提供清爽、高效的数字资产管理和交易体验。整体设计语言追求简洁、现代、专业，强调内容优先和操作效率。

设计系统基于移动端优先原则，默认画布宽度为 375px，最小高度为 812px。设计文件存储在 Figma，使用 Token 系统确保设计一致性。

## Colors
- **品牌主色** (#DF3136): 用于品牌强调、主要操作、交易按钮、价格高亮和重要提示。Token: `color/brand/primary`
- **品牌辅助色** (#356DC3): 用于链接、信息提示和次要操作。Token: `color/brand/secondary`
- **页面背景** (#F5F6F7): 移动端页面默认背景色。Token: `color/background/page`
- **卡片背景** (#FFFFFF): 用于卡片、面板、弹窗等内容容器。Token: `color/background/card`
- **浅色背景** (#F0F2F5): 用于标签默认态、图标底色和弱化区域。Token: `color/background/subtle`
- **主要文字** (#1E1E1E): 用于标题、正文、主要标签和关键信息。Token: `color/text/primary`
- **次要文字** (#666666): 用于辅助说明、时间戳和次要信息。Token: `color/text/secondary`
- **弱化文字** (#999999 / #A5A6A8): 用于禁用态、占位符和低优先级文本。Tokens: `color/text/tertiary`, `color/text/quaternary`
- **默认边框** (#E2E4E9): 用于组件边框、输入框和卡片轮廓。Token: `color/border/default`
- **浅色边框** (#EEEEEE): 用于分割线和轻量边框。Token: `color/border/subtle`
- **成功色** (#15A05A): 用于成功状态、已完成、已支付等正向反馈。Token: `color/function/success`
- **警告色** (#F59E0B): 用于警告、待处理、进行中等中性提示。Token: `color/function/warning`
- **错误色** (#FA3C3C): 用于错误、失败、危险操作等负向反馈。Token: `color/function/danger`
- **中性黑** (#000000): 用于确认、提交、保存等系统级操作。Token: `color/neutral/black`

颜色使用原则：品牌主色用于交易和强调，中性黑用于系统确认，状态色必须配合文字说明使用。

## Typography
- **中文字体**: HarmonyOS Sans SC, PingFang SC, Microsoft YaHei, sans-serif
- **英文字体**: Inter, SF Pro Text, system-ui, sans-serif
- **Figma 字体**: 优先使用 PingFang SC，不可用时回退到 Inter
- **品牌字体**: Alibaba PuHuiTi 3.0（用于品牌展示场景）

字号体系保持清晰的层级关系，移动端正文不小于 12px。字距统一为 0，不使用负字距。

**字号规范**：
- Hero Number: 32/38 Bold — 用于关键数字、价格
- Title Large: 24/32 Semi Bold — 用于页面主标题
- Title: 22/28 Semi Bold — 用于区块标题
- Title Small: 20/26 Semi Bold — 用于卡片标题
- Nav Title: 17/23 Semi Bold — 用于导航栏标题
- Body Large: 16/24 Regular — 用于重要正文
- Body: 14/20 Regular — 用于标准正文
- Body Medium: 14/20 Medium — 用于强调正文
- Body Small: 12/16 Regular — 用于辅助说明
- Label Medium: 12/16 Medium — 用于标签
- Assist: 11/15 Regular — 用于次要提示
- Caption: 10/14 Regular — 用于图注
- Tab: 9/12 Regular — 用于底部标签栏

## Elevation
采用克制的层级设计。大多数卡片使用平面设计（白色背景 + 1px 边框），不使用阴影。仅在需要明确表达浮层关系时使用轻微阴影。

- **默认卡片**: 白色背景 + 浅色边框，无阴影
- **浮层卡片**: `0 8px 20px -8px rgba(0,0,0,0.05)` 或 token `color/shadow/soft`

避免使用装饰性阴影、发光效果和无关渐变。层级只用于表达功能关系，不用于装饰。

## Components

### 按钮
- **主按钮（红色）**: 用于交易、购买、提交订单等核心操作
- **主按钮（黑色）**: 用于确认、保存、绑定、下一步等系统操作
- **次要按钮**: 用于取消、稍后、返回等次要操作
- **幽灵按钮**: 用于编辑、查看详情等低干扰操作
- **危险按钮**: 用于删除、退出登录等不可逆操作

**尺寸规范**：
- 底部 CTA: 343×52
- 表单按钮: 高度 44px
- 卡片操作按钮: 高度 29px 或 32px

同一屏幕避免出现多个主操作按钮。

### 卡片
用于承载内容分组，固定宽度 355px，圆角 8px，白色背景。卡片之间间距 10px。

**内容规范**：
- 内边距: 16px
- 标题与内容间距: 12px
- 内容行间距: 8px

### 列表项
用于设置、账户信息等场景。

**规范**：
- 分组宽度: 355px
- 行宽: 323px
- 行高: 54px
- 分割线: 0.5px
- 左侧标签 + 右侧值 + 可选箭头

敏感信息必须脱敏显示（如 `139****0000`）。

### 分段控制
用于同页面内容筛选或状态切换。

**规范**：
- 单项尺寸: 64×24
- 项间距: 10px
- 圆角: 胶囊形（999px）
- 选中态: 黑底白字
- 默认态: 浅灰底 + 主要文字

使用 2-5 个互斥选项，文案保持简短。

### 输入框
**规范**：
- 高度: 44px
- 圆角: 8px
- 边框: 1px 默认边框色
- 内边距: 12px 横向
- 占位符: 弱化文字色

聚焦态使用品牌主色边框，错误态使用错误色边框。

## Spacing
使用 4px 基础网格系统，常用间距值：

- **4px**: 最小间距，用于紧密相关元素
- **8px**: 小间距，用于组内元素
- **12px**: 标准间距，用于卡片内部
- **16px**: 常用间距，用于区块间隔
- **20px**: 中等间距，用于模块分隔
- **24px**: 大间距，用于页面区块
- **32px**: 特大间距，用于重要分隔

**页面级间距**：
- 页面左右边距: 10px
- 卡片宽度: 355px
- 底部 CTA 宽度: 343px

## Border Radius
- **2px**: 极小细节
- **4px**: 小控件
- **6px**: 图片、图标
- **8px**: 标准卡片
- **12px**: 大面板
- **16px**: 强调容器
- **20px**: 大型面板
- **999px**: 按钮、标签、胶囊

保持圆角使用的一致性，避免在同一屏幕混用无关圆角值。

## Layout Patterns

### 首页布局
1. 顶部导航/状态栏
2. 轮播或焦点内容区
3. 功能入口区（网格或列表）
4. 内容推荐区
5. 底部导航栏

### 列表页布局
1. 导航标题
2. 搜索/筛选区
3. 列表内容（卡片或行）
4. 空状态提示
5. 加载更多

### 详情页布局
1. 导航标题
2. 主视觉/摘要
3. 核心信息卡片
4. 详细信息区
5. 相关推荐
6. 底部操作区

### 表单页布局
1. 导航标题
2. 表单说明（可选）
3. 输入字段组
4. 提示/规则说明
5. 底部提交按钮

## Icons
所有图标使用统一的图标系统，尺寸规范：

- **16px**: 小图标（标签、提示）
- **20px**: 标准图标（列表、按钮）
- **24px**: 大图标（导航、功能入口）
- **32px**: 特大图标（空状态、引导）

图标颜色跟随文字颜色或使用品牌色强调。

## Do's and Don'ts

**Do**:
- 使用 Token 系统定义的颜色、间距、圆角
- 保持移动端页面宽度 375px
- 品牌主色用于交易和强调，中性黑用于系统确认
- 敏感信息必须脱敏
- 模块间保持合理间距（16/20/24px）
- 使用图标系统中的标准图标
- 状态必须配合文字说明

**Don't**:
- 不要硬编码颜色值，使用 Token
- 不要创建新的基础组件样式
- 不要使用 emoji 或字符代替图标
- 不要混用品牌主色和中性黑的语义
- 不要卡片嵌套卡片
- 不要使用装饰性渐变或发光效果
- 不要让独立模块意外重叠

## Accessibility
- 文字与背景对比度至少 4.5:1
- 可点击区域最小 44×44px
- 重要操作提供明确反馈
- 表单错误提供清晰提示
- 支持动态字体缩放

## Responsive
虽然以移动端为主，但设计应考虑不同屏幕尺寸：

- **小屏**: 320px - 375px
- **标准**: 375px - 414px
- **大屏**: 414px+

关键内容和操作在小屏上也应完整可用。
